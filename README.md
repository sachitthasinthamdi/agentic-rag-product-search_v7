# Agentic RAG vs RAG สำหรับการค้นหาสินค้าสองภาษา

โครงงานเปรียบเทียบสถาปัตยกรรม **RAG มาตรฐาน** กับ **Agentic RAG** บนระบบแนะนำสินค้าเชิงสนทนา
ที่รับคำถามได้ทั้งภาษาไทยและอังกฤษ บนคลังสินค้า Amazon ภาษาอังกฤษ 81,264 รายการ
ประมวลผลบนเครื่องส่วนบุคคลทั้งหมด ไม่เรียกบริการแบบจำลองภาษาผ่านเครือข่าย

## ผลหลัก

| ภาษา | A1 (RAG) | A3C · A3 (Agentic) | ชนะ · แพ้ | p |
|---|---|---|---|---|
| อังกฤษ | 0.3288 | **0.3564** | **8 · 0** | **0.0078** |
| ไทย | 0.3165 | **0.3267** | **5 · 0** | 0.0625 |

วัดด้วย nDCG@3 บนชุดทดสอบ 140 คำค้น · ทดสอบจับคู่แบบสลับเครื่องหมายนับครบทุกกรณี
ค่า 0.0625 ของฝั่งไทยเป็นค่าต่ำสุดที่เป็นไปได้เมื่อมีข้อที่ต่างกัน 5 ข้อ ($2/2^5$)

**ข้อค้นพบที่สำคัญกว่าผลหลัก** — ชั้นจัดอันดับทำให้สินค้าที่ตรงสูญหาย 45–48%
ซึ่งมากกว่าทุกชั้นอื่นรวมกันราว 3.5 เท่า และการเพิ่มสัญญาณนับคำซ้อนเข้าไปในชั้นนั้น
ให้ผลมากกว่าการเพิ่มความเป็นเอเจนต์ประมาณ 2 เท่า

## สถาปัตยกรรมที่เปรียบเทียบ

ทุกแบบใช้โมดูลร่วมกันทั้งหมด ต่างกันเฉพาะชั้นที่แบบจำลองภาษาตัดสินใจเอง

| | เลือก ถาม/คุย/ค้น | ตัดสินว่าจะค้นซ้ำ | จัดเป็น |
|---|---|---|---|
| **A1** | — | — (ค้นรอบเดียว) | RAG มาตรฐาน |
| **A3C** | LLM | กฎในโปรแกรม | Agentic RAG |
| **A3** | LLM | LLM | Agentic RAG |

# เริ่มใช้งาน

## 1. สิ่งที่ต้องมีก่อน

| รายการ | รุ่นที่ใช้พัฒนา |
|---|---|
| Python | 3.12 |
| [Ollama](https://ollama.com) | 0.32 |
| หน่วยความจำกราฟิก | 8 GB (ต่ำกว่านี้โมเดล 8B จะช้ามาก) |
| พื้นที่ว่าง | ~2 GB สำหรับข้อมูล + ~6 GB สำหรับโมเดล |

## 2. ติดตั้ง

```bash
git clone https://github.com/sachitthasinthamdi/agentic-rag-product-search_v7.git
cd agentic-rag-product-search_v7

python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

pip install -r requirements.txt
```

## 3. โหลดแบบจำลองลงเครื่อง

```bash
ollama pull scb10x/llama3.1-typhoon2-8b-instruct
ollama pull bge-m3
```

ตัวแรกใช้วางแผน แปลภาษา และเขียนคำตอบ ตัวที่สองใช้ฝังเวกเตอร์

เปิดบริการไว้ตลอดเวลาที่ใช้งาน

```bash
ollama serve
```

## 4. โหลดข้อมูลจาก HuggingFace

ข้อมูลที่ผ่านการเตรียมแล้วเผยแพร่ไว้ที่
[`sachittha/amazon-products-agentic-rag`](https://huggingface.co/datasets/sachittha/amazon-products-agentic-rag)
จึง**ข้ามขั้นตอนเตรียมข้อมูลทั้งหมดได้** ใช้คำสั่งเดียว

```bash
python tools\download_data.py
```

ได้ไฟล์ประมาณ 340 MB

| ไฟล์ | ขนาด | เนื้อหา |
|---|---|---|
| `data/feature/products_feature.feather` | 182 MB | คลังสินค้า 81,264 แถว 16 คอลัมน์ |
| `data/vectors/bge-m3_v1.npy` | 159 MB | เวกเตอร์ 81,264 × 1,024 |
| `data/vectors/bge-m3_v1.ids.feather` | 1 MB | รหัสสินค้าเรียงตรงกับเวกเตอร์ |
| `data/vectors/bge-m3_v1.meta.json` | เล็ก | ข้อมูลกำกับของรอบที่ฝัง |

เพิ่ม `--testcollection` ถ้าต้องการชุดทดสอบพร้อมเฉลยจาก
[`sachittha/thai-English-product-search-testcollection`](https://huggingface.co/datasets/sachittha/thai-English-product-search-testcollection)
ด้วย (ไม่จำเป็นสำหรับการรัน เพราะโปรเจกต์มีไฟล์ชุดนี้อยู่แล้วใน `eval/`)

ทั้งสองชุดเป็นสาธารณะ **ไม่ต้องใช้โทเคน**

## 5. สร้างดัชนีค้นหา

```bash
python src\build_index.py --reset
```

ใช้เวลาไม่กี่นาที ได้ฐานข้อมูลเวกเตอร์ Chroma ที่ `data/chroma/`

ตรวจว่าใช้ได้

```bash
python tools\test_rerank.py
```

# การใช้งาน

## หน้าจอสาธิต — เลือกสถาปัตยกรรมได้ในหน้าเดียว

```bash
python demo\server.py
```

เปิด `http://127.0.0.1:8000`

เลือกได้ว่าจะใช้ A1, A3C หรือ A3 หรือเปิดโหมด **เทียบทั้งสามแบบพร้อมกัน**
ใต้คำตอบแต่ละแบบมีแถบตัวเลขจากการทำงานจริง คือจำนวนครั้งที่เรียกแบบจำลอง
จำนวนครั้งที่ค้น จำนวนผู้เข้าชิง และจำนวนที่ผ่านเกณฑ์คัด

> **ก่อนถามคำถามใหม่ที่ไม่เกี่ยวกับคำถามก่อน ให้กดปุ่ม "ล้างความจำ"**
> เพราะแต่ละสถาปัตยกรรมจดจำบทสนทนาข้ามรอบ ถ้าไม่ล้าง ลูปค้นซ้ำจะไม่ทำงานให้เห็น

## คุยผ่านบรรทัดคำสั่ง

```bash
python src\a1.py        # RAG มาตรฐาน
python src\a3c.py       # Agentic RAG — เอเจนต์เลือกการกระทำ
python src\a3.py        # Agentic RAG — เอเจนต์คุมการค้นซ้ำด้วย
```

## รันการทดลองซ้ำทั้งชุด

```bash
# ฝั่งอังกฤษ ทั้งสามแขน ครั้งละรอบ  (ใช้เวลาราว 1.5 ชั่วโมง)
python eval\run_collection.py --arms A1 A3C A3 --rounds 1 --lang en

# ฝั่งไทย
python eval\run_collection.py --arms A1 A3C A3 --rounds 1 --lang th
```

ผลเก็บเป็นไฟล์ JSON ใน `eval/results/`

## คิดตัวชี้วัด

```bash
# ตัวชี้วัดที่ใช้เฉลย แยกตามกลุ่มคำค้น
python eval\metrics_labelled.py eval\results\<ชื่อไฟล์ผล>.json

# เทียบสามแขนบนชุดคำค้นร่วม พร้อมทดสอบนัยสำคัญ
python eval\verify\arms_common.py eval\results\<ชื่อไฟล์ผล>.json
```

> `arms_common.py` มีค่าเริ่มต้นเป็นไฟล์ผลเก่า **ต้องระบุชื่อไฟล์ผลเสมอ**

ไฟล์ผลที่ใช้รายงานในวิทยานิพนธ์คือ
`eval/results/collection_20261017_1213.json` (อังกฤษ) และ
`eval/results/collection_th_20261017_1350.json` (ไทย)

# เส้นทางยาว — เตรียมข้อมูลเองตั้งแต่ต้น

ไม่จำเป็นถ้าโหลดจาก HuggingFace แล้ว ใช้เมื่อต้องการเปลี่ยนคลังสินค้าหรือวิธีสกัดคุณลักษณะ

# ข้อจำกัดที่ควรรู้ก่อนนำไปใช้

1. แบบจำลองภาษาขนาด 8 พันล้านพารามิเตอร์ ข้อสรุปสรุปไปถึงแบบจำลองใหญ่กว่าไม่ได้
2. คำค้นภาษาไทยในชุดทดสอบได้จากการแปล ไม่ใช่คำที่ผู้ใช้ไทยพิมพ์เอง
3. เฉลยติดโดยผู้วิจัยซึ่งเป็นผู้พัฒนาระบบเอง ยังไม่มีผู้ติดป้ายอิสระคนที่สอง
4. กองที่ติดเฉลยมาจากสินค้าที่ระบบนี้หยิบขึ้นมา ระบบอื่นที่หยิบของนอกกองจะถูกประเมินต่ำกว่าจริง
5. ตัวหารของ nDCG ใช้ระบบในอุดมคติ จึงเทียบกับงานอื่นที่ใช้ตัวหารแบบอื่นโดยตรงไม่ได้

ข้อจำกัดฉบับเต็มอยู่ในบทที่ 5 ของวิทยานิพนธ์

# ปัญหาที่พบบ่อย

**`ConnectError … actively refused it`** — ยังไม่ได้เปิด Ollama ให้รัน `ollama serve` ก่อน

**ค้นแล้วไม่เจออะไรเลย** — ยังไม่ได้สร้างดัชนี ให้รัน `python src\build_index.py --reset`

**ลูปค้นซ้ำไม่ทำงานในหน้าสาธิต** — ระบบจำคำถามก่อนหน้าไว้ ให้กด "ล้างความจำ" ก่อน

**ตัวเลขที่ได้ไม่ตรงกับในวิทยานิพนธ์** — ตรวจว่าระบุไฟล์ผลที่ถูกต้องให้สคริปต์วัดผลแล้วหรือยัง
