**สถานะ: ✅ ตัดสินครบ 3 ข้อแรกแล้ว (2 ต.ค. 2026)** — ข้อ 4-6 รอตอนถึงขั้นนั้น

# ตัดสินใจตอนนี้ 3 ข้อ

## ตัดสินใจที่ 1 — ขอบเขตข้อมูล: ใช้กี่แถว?

**สิ่งที่ข้อมูลบอก:** 30 หมวดจาก `filename` มีขนาดต่างกันสุดขั้ว — ใหญ่สุด 41,777 แถว
เล็กสุด 2 แถว และบางหมวดไม่ใช่ "สินค้าที่แนะนำกันได้" จริง ๆ

| ตัวเลือก | เหลือกี่แถว | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **1ก. ใช้ทั้งหมด** | 117,243 | ไม่ต้องอธิบายว่าตัดอะไรทิ้ง · ครอบคลุมสุด | มีหมวดที่แนะนำไม่ได้ปนอยู่ (บัตรของขวัญ 8, นิตยสาร 3, หนังสือ 2) |
| **1ข. ตัดหมวดจิ๋วและหมวดที่ไม่ใช่สินค้าจับต้องได้** ⭐ | ~114,900 | ตัด `Gift_Cards`(8) `Magazine_Subscriptions`(3) `Books`(2) `Software`(157) `Digital_Music`(56) `CDs_and_Vinyl`(1,319) `Unknown`(541) — รวม ~2,086 แถว (1.8%) · เหตุผลอธิบายได้ชัด | เสียความครอบคลุมนิดหน่อย |
| **1ค. เลือกเฉพาะ 8-10 หมวดใหญ่** | ~95,000 | ข้อมูลสมบูรณ์กว่า ทดลองเร็วกว่า | ตัดทิ้ง 19% · ต้องอธิบายเกณฑ์การเลือกให้ดี |

**ผมแนะนำ 1ข.** — ตัดเฉพาะที่มีเหตุผลชัดเจน (สินค้าดิจิทัล/บริการ/หมวดที่เล็กจนไม่มีอะไรให้แนะนำ)
ไม่ใช่ตัดเพราะอยากให้ข้อมูลน้อยลง และเสียไปแค่ 1.8%

---

## ตัดสินใจที่ 2 — หมวดสินค้า: ใช้แหล่งไหน?

หมวดสำคัญเพราะจะใช้ทั้ง**กรองตอนค้นหา** และ**ตรวจว่าแนะนำตรงประเภทไหม**

| ตัวเลือก | ผล |
|---|---|
| **2ก. `filename` เป็นหลักอย่างเดียว** ⭐ | ครบ 100% (ยกเว้น 541 แถว `Unknown` ที่จะถูกตัดไปแล้วถ้าเลือก 1ข.) · 30 หมวดสะอาด |
| **2ข. `main_category` เป็นหลัก เติมด้วย `categories[0]` แล้วค่อย `filename`** | ครบ 100% เหมือนกัน แต่ค่าปนกัน 3 ระบบ ทำให้กรองยาก |
| **2ค. เก็บทั้ง 3 เป็นคนละฟิลด์** | ข้อมูลครบสุด แต่ต้องตัดสินใจอยู่ดีว่าจะใช้อันไหนตอนกรอง |

**ผมแนะนำ 2ก. + เก็บ `categories` ไว้เป็นฟิลด์เสริม** สำหรับหมวดย่อย (เช่น
`['Musical Instruments', 'Drums & Percussion', 'Drum Sets']`) ซึ่งมีประโยชน์ตอนอยากกรองละเอียด

---

## ตัดสินใจที่ 3 — ราคาที่หายไป 30.6% (35,869 แถว)

นี่คือช่องโหว่ใหญ่สุดของข้อมูล และกระทบโดยตรงเพราะผู้ใช้มักถามถึงงบประมาณ

| ตัวเลือก | เหลือกี่แถว | ผล |
|---|---|---|
| **3ก. เก็บไว้ ปล่อยว่าง + ทำเครื่องหมายว่า "ไม่มีราคา"** ⭐ | 117,243 | ค้นเจอได้ทุกชิ้น · แต่ถ้าผู้ใช้ถามงบ สินค้า 30% จะกรองไม่ได้ · ต้องบอกผู้ใช้ตรง ๆ ว่า "ไม่ระบุราคา" |
| **3ข. ตัดแถวที่ไม่มีราคาทิ้ง** | 81,374 | ทุกชิ้นกรองราคาได้ · **แต่เสียข้อมูลไป 30%** และเสียแบบไม่สุ่ม (บางหมวดหายทั้งหมวด) |
| **3ค. เติมด้วยราคากลางของหมวด** | 117,243 | กรองได้ทุกชิ้น · **แต่เป็นการแต่งตัวเลขขึ้นมา** ถ้าเอาไปบอกผู้ใช้ว่าเป็นราคาสินค้าคือให้ข้อมูลเท็จ |

### ✅ ตัดสิน: เลือก 3ข. — ตัดแถวที่ไม่มีราคาทิ้ง

ราคา ≤ 0 จำนวน 110 แถว นับเป็น "ไม่มีราคา" ด้วย (ราคา 0 เป็นไปไม่ได้จริง) → **เหลือ 81,264 แถว (69.3%)**

**สิ่งที่ได้:** ทุกสินค้าในคลังมีราคา → กรองตามงบได้ 100% และคำนวณ "ความคุ้มค่า"
(คะแนน ÷ ราคา) ได้ทุกชิ้น ซึ่งเป็นสัญญาณสำคัญตอนจัดอันดับ

**สิ่งที่เสีย:** สินค้าหายไป 1 ใน 3 — เสื้อผ้าหาย 11,433 ชิ้น ของใช้ในบ้านหาย 5,827 ชิ้น
ถ้าผู้ใช้ถามหาของที่อยู่ในกลุ่มที่ไม่มีราคา ระบบจะไม่มีวันเจอ

**ผลกระทบรายหมวด (วัดแล้ว):** กระจายค่อนข้างสม่ำเสมอ ไม่กระจุกที่หมวดใด

| หมวด | ทั้งหมด | เหลือ |
|---|---|---|
| Clothing_Shoes_and_Jewelry | 41,777 | 30,344 (72.6%) |
| Home_and_Kitchen | 17,326 | 11,499 (66.4%) |
| Electronics | 7,681 | 4,968 (64.7%) |
| Automotive | 7,161 | 4,910 (68.6%) |
| Sports_and_Outdoors | 6,343 | 4,297 (67.7%) |
| *(หมวดใหญ่อื่น ๆ)* | | เหลือ 59-87% |
| Appliances | 573 | 274 (47.8%) ⚠ |
| Software | 157 | 41 (26.1%) ⚠ |
| Magazine_Subscriptions | 3 | **0** ← หายทั้งหมวด (หมวดเดียว) |

> **ข้อควรระบุในเล่ม:** การตัดนี้ทำให้คลังเหลือ 69.3% และเป็นการตัด**แบบไม่สุ่ม**
> (สินค้าที่ไม่ระบุราคาอาจมีลักษณะต่างจากสินค้าทั่วไป) ต้องเขียนเป็นข้อจำกัดของงานวิจัย
>
> *หมายเหตุ: ก่อนหน้านี้ผมเตือนว่า "บางหมวดหายทั้งหมวด" ซึ่งเกินจริง — วัดแล้วมีแค่
> Magazine_Subscriptions ที่มีอยู่ 3 แถว*

# รอไว้ก่อน ค่อยตัดสินตอนถึงขั้นนั้น

## ตัดสินใจที่ 4 — จะสกัดคุณสมบัติอะไรจาก `details` (ขั้นที่ 3)

`details` แปลงเป็น dict ได้ **100%** มี key ถึง **3,308 ชนิด** (มัธยฐาน 7 key ต่อสินค้า)
ต้องเลือกว่าจะดึงอันไหนออกมาเป็นคอลัมน์

| key | มีกี่ % | น่าสนใจเพราะ |
|---|---|---|
| `Manufacturer` | 77.9% | แบรนด์ (ครอบคลุมกว่า `Brand`) |
| `Item model number` | 49.6% | ไม่มีประโยชน์เชิงค้นหา |
| `Brand` | 46.3% | แบรนด์ |
| `Best Sellers Rank` | 44.3% | ความนิยม — แต่รุ่นก่อนพิสูจน์แล้วว่าเทียบข้ามหมวดไม่ได้ |
| `Item Weight` | 43.3% | น้ำหนัก |
| **`Department`** | **39.3%** | ⭐ ผู้ชาย/ผู้หญิง/เด็ก — รุ่นก่อนต้องเดาเอาจากชื่อสินค้า ทั้งที่มีฟิลด์นี้อยู่ |
| `Color` | 34.9% | สี |
| `Material` | 26.3% | วัสดุ |
| `Size` | 10.8% | ขนาด |

## ตัดสินใจที่ 5 — ข้อความที่ใช้ค้นหา (ขั้นที่ 4)

ความยาวที่วัดได้: `title` มัธยฐาน 120 ตัวอักษร · `description` มัธยฐาน 520 (ยาวสุด 17,217) ·
`features` มัธยฐาน 5 ข้อ

ตัวเลือกคร่าว ๆ: ใช้ `title` อย่างเดียว / `title + features` / `title + features + description` /
รวม `details` ด้วย — ยิ่งยาวยิ่งช้าและอาจมี noise แต่ยิ่งครอบคลุม

## ตัดสินใจที่ 6 — สินค้าที่มีรีวิวน้อย (ขั้นที่ 3)

**17,171 แถว (14.6%) มีรีวิวแค่ 1 ครั้ง** และมัธยฐานของทั้งคลังคือ 10 รีวิว
สินค้า 5 ดาวจากรีวิวเดียวไม่ควรชนะสินค้า 4.5 ดาวจากพันรีวิว — จะแก้ด้วยสูตรถ่วงน้ำหนัก
หรือตัดทิ้ง ค่อยว่ากัน
