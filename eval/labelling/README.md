# eval/labelling — เครื่องมือติดป้าย

โฟลเดอร์นี้มีสองชุด

| ชุด | ไฟล์ | ใช้ทำอะไร |
|---|---|---|
| **ป้าย ก** ความตรงของสินค้า | `make_rank_pairs.py` · `show_rank.py` · `fill_rank.py` | ติดป้ายของที่**โผล่ใหม่หลังเปลี่ยนตัวจัดอันดับ** |
| **ป้าย ข** ความซื่อตรงของคำตอบ | `show_full.py` · `fill_b.py` · `make_*_labels.py` | ที่เหลือทั้งหมดในหน้านี้ |

ป้าย ก ชุดแรก (ก่อนเปลี่ยนตัวจัดอันดับ) ใช้ `eval/label_cli.py`

## ขั้นตอน

```bash
# 1. ดูคำตอบที่ยังไม่ติดป้าย (รอบ · เริ่มที่ข้อ · จำนวน)
.venv/Scripts/python.exe eval/labelling/show_full.py 4 1 6

# 2. ก๊อป batch.example.json เป็น batch.json แล้วใส่ป้ายของชุดนั้น
# 3. กรอกลงไฟล์ (เติมเฉพาะช่องที่ยังว่าง)
.venv/Scripts/python.exe eval/labelling/fill_b.py 4
```

## ⚠ สองกับดักที่เคยพลาดมาแล้ว

**1. ป้ายไหลข้ามรอบ** — `ans_id` (`f01`–`f49`) ซ้ำกันทุกรอบ เคยสั่งกรอกรอบ 3
แล้วป้ายของรอบ 4 ที่ค้างอยู่ในสคริปต์ไหลไปทับทั้ง 34 ข้อเงียบ ๆ
→ `batch.json` ต้องมีคีย์ `"round"` และ `fill_b.py` assert ว่าตรงกับรอบที่สั่ง
และพิมพ์รายการ `ans_id` ที่กรอกจริงออกมาทุกครั้ง

**2. ติดป้ายจากข้อมูลที่ถูกตัด** — `show_full.py` เคยตัดชื่อสินค้าที่ 96 ตัวอักษร
ทำให้เกือบติดป้ายผิด (คุณสมบัติที่ชี้ขาดอยู่เลยจุดตัด)
→ ตอนนี้พิมพ์ชื่อเต็มและรายละเอียด 300 ตัวอักษร **ก่อน** ติดป้าย

**3. บรรทัดเหตุผลเลื่อน** — ถ้าบรรทัดเหตุผลถูกตัวกรองทิ้ง บล็อกสินค้าจะมีแค่ 2 บรรทัด
ทำให้เหตุผลของชิ้นถัดไปเลื่อนขึ้นมาแทน → **เช็กช่อง `echoed` ก่อนเชื่อสิ่งที่เห็น**

## เกณฑ์ป้าย ข

| ป้าย | ความหมาย |
|---|---|
| 2 | ทุกข้อความมีข้อมูลรองรับ (รวมกรณีลอกชื่อสินค้ามาวางแต่ไม่เกินข้อมูล และกรณีตัวกรองทิ้งเหตุผลหมด) |
| 1 | ผิดคุณสมบัติ 1 อย่าง · ยกคุณสมบัติข้ามชิ้น · เติมคุณสมบัติที่ข้อมูลไม่บอก |
| 0 | ลอกคำค้นมาวางทั้ง 3 ชิ้นพร้อมมีชิ้นผิดประเภท · ข้อมูลมีแค่ชื่อแล้วแต่งคุณสมบัติเองทั้งประโยค · บรรยายตัวเครื่องแทนสินค้าที่ให้มา |

กฎพิเศษ 2 ข้อ — การทวนคำของผู้ใช้ไม่ถือว่าแต่งข้อมูล · การบอกตรง ๆ ว่าของไม่ตรงถือว่าดี ให้ 2
⚠ แต่การยัด**เงื่อนไขเฉพาะ**จากคำค้นทับข้อมูลจริง (ขนาด สี แบรนด์) ถือว่าผิด

`make_a1_labels.py` สร้างไฟล์ป้ายของแขน A1 ฝั่งไทย — ยกป้ายจาก A3 มา 47 คำค้นที่หยิบของเหมือนกัน
และใช้ป้ายที่อ่านคำตอบ A1 เองใน `q47` กับ `q49`

## ป้าย ก — ของที่โผล่ใหม่หลังเปลี่ยนตัวจัดอันดับ

**ทำไมต้องติดเพิ่ม** ตัวจัดอันดับเปลี่ยน (สัญญาณคำซ้อน + ข้อกำหนดที่ขาดไม่ได้)
คำค้นเดิม กอง 100 ชิ้นเดิม **แต่หยิบของคนละชิ้นขึ้น 3 อันดับแรก 51 จาก 80 คำค้น**
ของที่โผล่ใหม่ไม่มีป้าย `metrics_labelled.py` จึง**ตัดคำค้นนั้นทิ้งทั้งข้อ**
→ ชุดคำค้นร่วมเหลือ 21/50 และ 19 ใน 21 นั้นทุกแขนได้ผลเหมือนกันเป๊ะ
→ **p = 1.0000 ทุกช่อง วัดอะไรไม่ได้** (pooling bias · Zobel 1998)

```bash
# 1. สร้างไฟล์ป้ายจากผลการรัน (ไม่เขียนทับไฟล์ที่มีอยู่)
.venv/Scripts/python.exe eval/labelling/make_rank_pairs.py en

# 2. อ่านรายละเอียดทีละชุด (ภาษา · เริ่มที่คู่ที่ · จำนวน)
.venv/Scripts/python.exe eval/labelling/show_rank.py en 1 10

# 3. กรอกป้ายจากบรรทัดคำสั่ง
.venv/Scripts/python.exe eval/labelling/fill_rank.py en a8en001=3 a8en002=0
```

### 🔑 ปิดตาคนติดป้าย

ไฟล์ **ไม่บอกว่าแขนไหนหยิบของชิ้นนี้** และเรียงแถวด้วยค่าแฮชที่คงที่
ไม่ใช่เรียงตามแขนหรือตามคำค้น · เพราะถ้ารู้ว่าชิ้นนี้มาจาก A3C ป้ายจะเอนไปตาม
ความคาดหวังว่าแขนไหนควรชนะ ซึ่งเป็นผลที่โปรเจกต์กำลังพยายามวัดอยู่พอดี
ต้องการย้อนดูว่าแขนไหนหยิบ ให้ join ด้วย (รหัสคำค้น, ชื่อสินค้า) จากไฟล์ผลภายหลัง

### กันกับดักเดิมซ้ำรอย

`fill_rank.py` รับป้ายจาก**บรรทัดคำสั่ง** ไม่เก็บไว้ในโค้ด · **ปฏิเสธการเขียนทับ**
คู่ที่มีป้ายแล้วเว้นแต่สั่ง `--force` · และพิมพ์รหัสที่กรอกจริงออกมาทุกครั้ง
(กับดักข้อ 1 ด้านบนคือป้ายรอบ 4 ไหลไปทับรอบ 3 เงียบ ๆ 34 แถว)

`make_rank_pairs.py` ดึงคำบรรยายด้วย**รหัสสินค้า ไม่เรียก Ollama**
จึงสร้างไฟล์ได้ระหว่างที่การประเมินยังรันอยู่ ไม่แย่งทรัพยากร
